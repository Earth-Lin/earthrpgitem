EarthRPGItem 属性详细使用手册 2.3
================================

一、物品版本与旧物品失效
------------------------
item-version 是单件 RPGItem 的物品版本，不是插件版本。建议每次修改该物品属性后递增版本：

id: village_sword
item-version: 2
material: IRON_SWORD
attributes:
  Attack: 8

插件生成物品时会把 item-version 和当前注册属性指纹写入物品数据。
出现以下任意情况时，该物品被判定为旧物品，全部 RPG 属性不生效：
1. 物品保存的 item-version 与注册文件不同。
2. Attack、Armor、Fix、ExDur、技能战斗属性或原版属性等注册内容已经变化，属性指纹不同。
3. 物品来自 2.3 以前，没有物品版本或属性指纹。

旧物品放入 accessory 饰品 GUI 后同样不提供属性。旧物品描述中的英文属性不会被再次解析，因此不能绕过版本校验。
玩家把旧版 RPGItem 拿到主手或副手时，插件会按当前注册表自动重建为新版物品。更新会保留物品数量、原版耐久损耗、附加耐久损耗和灵魂绑定主人；随机属性按新版范围重新生成。
只放在背包或 accessory GUI 中的旧物品不会自动刷新。管理员也可以使用 /rpgitem give 玩家ID 物品ID 重新发放新版物品。
根节点 version: 2 也可使用，但推荐写 item-version: 2，含义更明确。

二、固定属性格式
----------------
display-name 会解析颜色代码。`&f` 和 `§f` 都是白色；例如 `&b` 是浅蓝色，`&6` 是金色，不能使用 `&f` 后再期待名称显示其他颜色。
插件同时支持 `&#00FFFF` 和 `&x&0&0&F&F&F&F` 十六进制颜色写法。YML 中建议把名称整体放在双引号内。

示例：

display-name: "&b星辉动力头盔<II>"
display-name: "&#00FFFF星辉动力头盔<II>"

护甲、武器和工具的名称使用同一个颜色解析器，YML、YAML、TXT 以及多物品节点格式行为一致。

原有数字格式继续有效，支持整数和小数：

attributes:
  Attack: 5
  MagicDamage: 7.5
  Armor: 3

普通非 RPGItem 物品的英文描述属性继续有效，即使前面带有 & 或 § 颜色代码也能识别：

Attack +5
&6Attack +5
§bArmor +3

注册 RPGItem 的 description 如果与 attributes 中同名，不会重复计算，避免双倍属性。

三、随机整数属性
----------------
范围格式为 最小值-最大值。插件会在物品生成时随机选取一个整数，并永久保存在这件物品中：

attributes:
  Attack: "5-9"
  Armor: "2-6"
  CritChance: "10-25"

Attack 可能得到 5、6、7、8 或 9，不会产生小数。默认每次属性结算重新随机，因此近战攻击、弓箭发射和受到伤害时都可能取得不同数值。
若旧物品缺少随机值 PDC，玩家把物品拿到主手或副手后会自动重新生成缺失的随机值。即使 PDC 异常，属性也至少回退到范围下限，不会变成 0。

随机模式可以在 config.yml 修改：

rpgitem:
  random-attributes:
    reroll-on-use: true

true：每次属性结算重新随机，Attack: "22-30" 的每次攻击都可能不同。
false：使用物品生成时保存的固定随机值，服务器重启后仍保持不变。

注意：本版本之前，这个开关从未被代码读取过。无论填 true 还是 false，物品都只在生成时随机一次，之后永久固定——这就是“40-60 只会随机选取一个数，然后一直固定伤害”的原因。

现在开关真正生效，默认值为 true。**插件会自动迁移旧配置**：启动时若 config.yml 里的 config-version 低于 2，插件会把 reroll-on-use 设为 true、写入 config-version: 2 并保存，同时在控制台打印迁移日志。因此不需要手动改这一项。

之所以能安全覆盖旧值：这个键在本版本之前没有任何代码读取，旧值（config.yml 里原本发的 false）从未产生过任何效果，不存在“用户本来就想用 false”的情况。迁移之后你再手动改成 false 才会被尊重。

启动时控制台会打印当前模式，便于确认：

  Random attributes: reroll-on-use = true (ranges are re-rolled per settlement)

`/rpgitem my` 面板顶部也会显示当前模式（“每次结算重掷”或“生成时固定”）。

负数范围可以写为 "-9--5"。百分比属性可以写对应属性名，例如：

attributes:
  AttackPercent: "10-30"
  Resistance: "-20--5"

四、描述中的随机属性
--------------------
普通物品描述支持随机范围：

&6Attack +5-9
&bArmor +2-4

注册 RPGItem 也可以只在 description 中提供随机属性：

attributes:
  Block: 10
description:
  - "&6Attack +5-9"
  - "&7这把武器会生成 5 到 9 的攻击属性"

只有 attributes 中没有配置 Attack 时，description 的 Attack +5-9 才作为注册属性，避免同名属性叠加。
如果 attributes.Attack 已存在，则描述行只负责显示文字。

五、YML、YAML 与 TXT
--------------------
.yml、.yaml、.txt 三种注册文件都支持固定属性和随机范围。多物品 YML 中每件物品独立配置：

items:
  random_sword:
    item-version: 1
    material: IRON_SWORD
    attributes:
      Attack: "5-9"
  random_armor:
    item-version: 3
    material: DIAMOND_CHESTPLATE
    attributes:
      Armor: "8-12"

六、使用建议
------------
1. 随机范围建议加双引号，避免 YAML 工具误判类型。
2. 修改属性后同时递增 item-version，并重新发放物品。
3. 不要手动修改物品内部 PDC；版本或属性指纹不一致会使属性失效。
4. reroll-on-use 为 true 时，物品描述与 /rpgitem my 属性面板都显示范围格式（例如 BowDamage +40-60），因为每次结算的取值都不同，写死一个数字会误导玩家；为 false 时两者都显示物品保存的固定随机值。
5. 原版物品英文描述属性没有注册表版本，仍按描述实时读取。

六点五、属性面板的范围显示
--------------------------
/rpgitem my 面板对每个带随机范围的属性都显示 最小值-最大值，例如：

  +BowDamage: 40-60 + 0%
  +Attack: 5-9 + 10%

其中百分比部分若也配了范围，会一并显示，例如 +Attack: 5-9 + 10-30%。
只有当 reroll-on-use 为 true 时才显示范围；为 false 时显示物品上保存的那个固定值。

本版本之前，面板只有 Attack 一项会显示范围，其余属性（BowDamage、Armor 等）都只显示单个数字，看起来像随机范围没有生效。现已统一。

被动刷新（PlayerAttributeTask，每秒一次）始终使用固定值，不参与重掷。原因是该任务每秒用 stats.health() 重写最大生命：如果这里也重掷，一件 Health: "10-20" 的装备会让玩家的最大生命每秒变化，血量被反复压低。因此战斗与命令结算重掷，被动同步保持稳定。

七、现有属性
------------
Attack、AttackPercent、Armor、ArmorPercent、CritChance、CritDamage、AttackSpeed、Health、Vitality、Recovery、LifeSteal、LifeStealPercent、MagicDamage、MagicDamagePercent、BowDamage、EXDraw、Fix/s、Fix/3s、ExDur、EnvArmor、MagicArmor、Resistance、BowArmor、CritArmor、Evasion、ArmorPen、TrueDamage、BackstrikeDamage、AssDamage、PctDamage、PstDamage、AttackRange、Parry、CounterAttack、Dodge、Block、Determination、CAD、IceDamage、FireDamage、LightDamage、DarkDamage 以及四类元素护甲继续使用原有计算规则。

随机范围适用于上述数值属性。BreakLimit、Soulbound、Deputy、unbreakable 等布尔开关仍使用 true 或 false。
