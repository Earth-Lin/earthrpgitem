EarthRPGItem 2.2 工作日志
========================

一、版本目标
------------
2.2 版本扩展 RPGItem 配置文件能力，允许使用标准 YML/YAML 文件，并支持在一个文件内注册多件物品；同时增加皮革护甲颜色配置。

二、配置文件兼容
----------------
1. Armor、Tool、Weapon、Accessory 目录同时识别 .txt、.yml、.yaml。
2. 原有 TXT 单物品格式不需要修改，继续使用原解析流程。
3. YML/YAML 支持传统单物品根节点结构，不填写 id 时以文件名作为默认 ID。
4. 新增 items 与 rpgitems 多物品根节点，每个子节点是一件完整 RPGItem。
5. 多物品节点键作为默认 ID，内部 id 字段可以覆盖该默认值。
6. 兼容直接在 YAML 根节点按物品 ID 排列多个物品，但推荐统一使用 items 包装层。

三、解析架构
------------
1. 多物品子节点会转换为独立配置作用域，再进入原有单物品加载器。
2. Attack、Armor、Fix、技能、吟唱、粒子、音效、Buff、附魔和描述等现有功能无需重复实现。
3. 注册文件按文件名稳定排序，便于定位重复 ID 和配置加载问题。
4. 非配置节点不会被错误注册为物品；格式错误的多物品子节点会输出包含文件路径和节点 ID 的警告。

四、模板生成
------------
1. 默认模板生成条件同步识别 .txt、.yml、.yaml。
2. 对应分类目录存在任意一种配置文件时，服务器启动不会再补写自带模板。
3. 对应目录完全没有配置文件时，才生成该分类的默认测试物品。

五、皮革护甲颜色
----------------
1. RpgItem 数据模型新增 leather-color。
2. 支持 RGB 格式，例如 leather-color: "255,0,0"。
3. 支持十六进制格式，例如 leather-color: "#2050FF"。
4. 颜色只应用于 LEATHER_HELMET、LEATHER_CHESTPLATE、LEATHER_LEGGINGS、LEATHER_BOOTS。
5. 无效颜色会输出后台警告并回退到原版皮革颜色，非皮革材质忽略此字段。

六、文档
--------
新增 tips/YML多物品与皮革颜色使用手册.txt，包含：
1. TXT、YML、YAML 单物品格式。
2. 单个 YML 文件注册多件物品的完整案例。
3. 多物品中的 FSkill、吟唱和伤害技能案例。
4. RGB 与十六进制皮革颜色案例。
5. give、puton、GUI 与模板生成兼容说明。

七、版本产物
------------
Gradle 项目版本更新为 2.2，构建产物名称为 EarthRPGItem-2.2.jar。

八、伤害数字前缀
----------------
1. DamageDisplay 新增按伤害类型读取 prefix 的逻辑，最终数字仍使用实际结算值。
2. 新增 physical、physical-crit、magic、magic-crit、bow、bow-crit、true、ice、fire、dark、light 共十一种前缀配置。
3. 前缀支持颜色代码、中文、英文与 Emoji，不要求填写 {damage}，插件自动把最终数字追加在前缀后。
4. 旧版 *-format 配置继续保留；存在对应 *-prefix 时优先使用前缀模式，不存在时回退完整格式模式。

九、伤害显示模板兼容修复
------------------------
1. 修复默认 prefix 配置直接覆盖旧版 *-format 模板的问题。
2. 新增 damage-display.prefix-enabled，默认 false；默认状态完整恢复 2.1 及更早版本的伤害显示模板。
3. 只有服主主动设置 prefix-enabled: true 时才启用自由前缀，避免插件升级改变已有服务器的显示样式。

十、锋利附魔伤害修复
--------------------
1. 排查确认 DamageDisplay 直接显示最终 physicalDamage，显示层没有独立漏算锋利伤害。
2. 部分原版伤害事件未提供完整 SHARPNESS 增伤时，战斗接管层现在按原版公式 0.5 × 等级 + 0.5 检测并补齐缺失部分。
3. 仅当事件原始伤害低于“攻击属性 + 锋利增伤”时补差值；事件已经包含锋利时不会重复叠加。
4. 补齐后的锋利伤害按原事件伤害保留防御减伤比例，再进入 RPG Armor、Resistance 和伤害数字计算。
5. YML enchantments 新增映射格式支持，同时继续兼容原有字符串列表格式。
十一、单个 YML 连续注册多件物品修复
----------------------------------
1. 修复同一文件连续出现多个顶层 id、material、attributes 时，标准 YAML 解析只保留最后一件物品的问题。
2. 加载器会在普通 YAML 解析前识别所有无缩进的顶层 id:，并将每个配置块独立解析和注册。
3. 用户可以直接把多件完整物品配置连续写入同一个 .yml 或 .yaml 文件，不要求额外添加 items: 包装节点。
4. 原有 items:、rpgitems:、根节点多物品、单物品 YML/YAML 与 TXT 配置全部继续兼容。
5. 后台会打印当前连续多物品文件成功注册的物品数量，便于排查配置加载情况。
